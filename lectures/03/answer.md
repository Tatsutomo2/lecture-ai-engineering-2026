# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：「AIE2026の講座の宿題にある『3レベル』とは何ですか？」という同じ質問で比べた。 素のLLM（app.ask）は講座独自の知識を持たないため、「一般的には3段階の課題を指す」と 推測ベースの長い回答を返した。ただ、「分からない」と投げ出すのではなく、前置きをした上で なんとか要望に応えようとする姿勢が見え、回答に怖さは感じなかった。 一方、エージェント（app.agent）は用語集の内容に基づいて、「基礎・実装・発展の3段階で どれか1つで完了」と用語集の定義どおりに回答し、末尾に「関連する回：第1回」と付記した。

- `--trace` で見えたツール呼び出し（ツール名と引数）： 質問によってツールの使われ方が変わることを確認できた。 「LoRAとQLoRAの違いは？」では、search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) のように、検索ツールが2回に分けて呼ばれた。 一方、「第2回の内容から確認問題を1問出して」では、make_quiz({'lecture': 2}) が1回だけ呼ばれた。

- 1つの質問での LLM 呼び出し回数（`requests`）：どちらの質問でも requests は2回だった。1回目でどのツールを使うか判断し、 2回目でその結果をもとに最終的な回答を生成している。 なお、ツールの実行回数（tool_calls）は、LoRAの質問が2回、確認問題が1回だった。

- 追加したツールと、docstring に書いた説明：指定した回の用語から1つを選び、問題と答えを返すツール make_quiz(lecture: int) を追加した。 docstring には「『第2回の確認問題を出して』のように、復習用の問題を求められたときに使う」と 具体的な用途を書いた。プログラムの一部でありながら自然言語で設定を書くため、 人間に仕事の指示を出しているような感覚になった。 エージェントに意図どおり動いてもらうには、誤解を生まず、分かりやすい説明文を書くことを意識したい。

## 宿題

- 取り組んだレベル：基礎

- やったこと： search_glossary の docstring の「query には調べたい用語を1つだけ入れる」を 「まとめて入れる」に1か所だけ変え、変更前と同じ質問 「LoRA とQLoRAの違いは？」を --trace 付きで実行した。 実験のあとは git restore で元に戻した。

- 結果：変更前は search_glossary({'query': 'LoRA'}) と search_glossary({'query': 'QLoRA'}) の 2回（tool_calls=2）だったが、変更後は search_glossary({'query': 'LoRA QLoRA'}) の 1回（tool_calls=1）になった。requests はどちらも2だった。 回答は、2つの用語の違いを説明する内容で、見た目の違いを除けばほぼ同じだった。 （今回の1回の実行での結果）

- 気づき・疑問：ログラムがツールそのもので、docstring はその説明書のようなものだと感じた。 今回の実験でも、コードは一切変えず、説明文の「1つだけ」を「まとめて」に変えただけで、 モデルのツールの呼び方が変わった。 一度ツールを作ってしまえば、その使い方は自然言語で指示できる。 そのため、使い方を変えるたびにプログラムを改修するよりも、作業は比較的楽にできると感じた。 疑問：複数の用語をまとめて検索する方式は、用語集の検索のしくみ次第で 取りこぼしが出ないか。
